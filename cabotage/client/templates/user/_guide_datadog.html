Send application stdout and stderr to your own Datadog account. Export stays off until you enable it for an application environment.

Already using Datadog?

Keep your existing DD_API_KEY value and flags unchanged. Log export adds a separate collector; it does not replace your metrics/APM Agent or change its destination.

Enable log export

An organization Admin can make these changes. Select your application and environment, then open Config → Logging.

  1. Choose your destination and enable export.
    DD_API_KEY
    Leave the API key field blank to keep the existing key. A replacement is stored as a runtime secret and also changes the key used by the metrics/APM Agent.
    DD_SITE
    Select your account's Datadog site. This sets the log destination only.
    DD_LOGS_ENABLED
    Choose Enabled, then save. An API key alone never enables export.

    Logging and Config → Variables edit the same settings; changes in either appear in the other. Shared values stay inherited unless you explicitly choose an application override.

    Test saved destination sends one synthetic message using saved settings, even while export is disabled. Intake acceptance does not verify the application collector or enable export.

  2. Create a release, then deploy it.

    Use the application's Overview tab. Logging shows whether saved settings are included in the last completed deployment or require deployment; it does not report delivery health. No image rebuild is needed for a configuration-only change.

  3. Check Datadog Live Tail.

    Emit a non-sensitive log message and search for service:<application-slug>. Confirm it reaches the intended account.

What gets exported

Only application process logs, including workers and release, postdeploy, and scheduled jobs. Cabotage's log viewer and existing Alloy/Loki collection keep working.

Project/environment variables can be shared through explicit application subscriptions. Subscribe the enable flag only in applications you want to export; there is no organization-wide switch.

Delivery is best-effort, not an audit archive. Collector crashes, pod removal, prolonged outages, and short-job shutdown can lose logs.

Turn off export

Choose Disabled in Logging, or set DD_LOGS_ENABLED=false in Variables, then create a release and deploy it. Keep the API key if your metrics/APM Agent uses it. Already-running jobs retain their original settings.

Troubleshooting

Deployment rejects the key or site {{ icon('chevron-right', 'guide-disclosure-icon') }}

Check that the application has a readable DD_API_KEY and an explicit DD_SITE; platform credentials are never used as a fallback.

Supported sites: datadoghq.com, datadoghq.eu, us3.datadoghq.com, us5.datadoghq.com, ap1.datadoghq.com, ap2.datadoghq.com, uk1.datadoghq.com, ddog-gov.com, and us2.ddog-gov.com.

Pods are running, but logs are missing {{ icon('chevron-right', 'guide-disclosure-icon') }}

Confirm the new release was deployed and the key belongs to the selected site. Ask your platform operator to inspect the datadog-logs container for mounting, authentication, or network errors; do not paste API keys into support messages.

Logs arrive as JSON text {{ icon('chevron-right', 'guide-disclosure-icon') }}

Application JSON is preserved in the message. Configure a Datadog parsing pipeline and field remappers for your application's message, severity, timestamp, and trace IDs.

For platform operators {{ icon('chevron-right', 'guide-disclosure-icon') }}
  • The collector is Fluent Bit 4.2.2; override its image with CABOTAGE_DATADOG_LOGS_IMAGE. The existing Agent image is unchanged.
  • Requires Linux CRI /var/log/pods, native sidecars, the lifecycle sleep hook, and read-only hostPath/subPathExpr mounts. Only the collector mounts its own pod directory.
  • Per collector: requests 32Mi / 10m, limits 128Mi / 100m, a 5M input buffer, and 16Mi of offset storage, not a durable output queue.
  • The key is in the container environment; restrict access to workload specifications. Verify mounting, short-job shutdown, and delivery on your cluster before rollout.
  • Opted-in pods exclude shared Datadog log collection, not metrics/APM. Deployments retain this exclusion after opt-out; remove it only if shared-account logging is intended. CronJob replacement uses the new annotations.
